# TURBO_GORSHOK

## Генератор интеграций с платёжными провайдерами на основе OpenAPI-спецификаций.

Проект автоматизирует создание шаблонов клиентского кода для работы с платежными API, используя декларативные эвристики. Система построена вокруг последовательной обработки данных через несколько слоёв.

На диаграмме представлен схематичный процесс генерации сервиса. Отметим, что при генерации фикстур и документации схема такая же, только без использования драйверов и хэндлеров эвристик.

<img width="2924" height="1213"  alt="canvas" src="https://github.com/user-attachments/assets/491d6225-c94c-446d-8f9c-14cb35bb2ba6" />

- **heuristic** – извлечении специфической информации из распарсенной препроцессором OpenAPI спецификации.
- **Preprocessor** – обрабатывает OpenAPI-спецификацию, извлекает и структурирует нужные данные для последующих этапов в виде класса ServiceManifest, который подается пайплайном на вход рендеру.
- **Pipeline** – объединяет этапы генерации в единый поток, управляет порядком выполнения. После окончаниия генерации через Writer сохраняет файлы.
- **heuristic_handler** – реализует специфическую логику применения эвристик к данным и генерирует код.
- **Driver** – отвечает за генерацию конкретного метода/методов на основе результата работы heuristic_handler.
- **Render** – собирает методы, сгенерированные драйверами в единный класс.

Генерация кода была реализована преймущественно за счет ERB шаблонов.

## Добавление нового функционала в генерируемый сервис
- Для генерации нового функционнала необходимо реализовать новый Driver и добавить его в драйверы ServiceRenderer. ServiceRenderer будет передавать ему информацию из класса ServiceManifest и потом добавлять сгенерированный метод в класс сгенерированноо сервиса.
- Если ServiceManifest не достаточно и новый функционал требует специфических информации, которую можно извлечь из голой openAPI спецификации, тогда можно написать свой класс Heuristic (эвристика). Нужно будет добавить написанную эвристику в соответствующий массив в классе препроцессора.
  ```ruby
   HEURISTICS = [CreateEndpointHeuristic, WebhookSigningHeuristic, DigitalSigningHeuristic,
                DataFieldsEncryptionHeuristic].freeze
  ```
- Далее необходимо добавить обработчик для написанной (Handler) эвристики и подключить его к соответствующему драйверу.
- После реализации драйвера, нужно добавить их в Service Renderer.

Добавление новых файлов, например, автотестов, реализуется через создание нового Renderer. После его реализации, его можно подключить в Pipeline.

## Запуск ##

Чтобы запустить генерацию, необходимо выполнить, следующие команды из корня решения. !!! решение разрабатывалось под linux и файл generate_provider - обычный руби файл с добавлением права на исполнение через chmod, поэому под windows это может не работать. 
```bash
mkdir generated
./bin/generate_provider -i yaml_examples/provider_api.yaml -o generated            
```
Стоит обратить внимание, что в команде указана спецификация из тестового задания. При необходимости ее можно заменить на другую
